# طراحی MVP — کاتالوگ‌یار

## هدف نسخه‌ی اول
کوچک‌ترین حلقه‌ی کامل ارزش: فروشنده عکس محصول را می‌فرستد و بدون پر کردن فرم، یک پیش‌نویس کاتالوگ کامل دریافت می‌کند که فقط باید تأیید/ویرایش جزئی کند.

## ورودی (Input)

| فیلد | نوع | اجباری | توضیح |
|---|---|---|---|
| `images` | لیست فایل تصویر یا ویدئو (۱ تا ۵) | بله | عکس/ویدئوی محصول؛ ویدئو با ffmpeg به فریم تبدیل می‌شود |
| `voice_note` | فایل صوتی فارسی (اختیاری) | خیر | توضیح شفاهی فروشنده درباره‌ی محصول |
| `seller_hint` | متن آزاد کوتاه (اختیاری) | خیر | مثلاً «این یه گیوه دست‌بافه» — کمک به مدل |
| `store_category_list` | لیست دسته‌بندی‌های مجاز پلتفرم | خیر (توصیه‌شده) | برای اینکه خروجی dropdown پلتفرم را رعایت کند |

## خروجی (Output)

```json
{
  "title": "string — عنوان پیشنهادی محصول",
  "category": {
    "suggested": "string",
    "confidence": 0.0
  },
  "description": "string — توضیح محصول آماده انتشار",
  "attributes": [
    { "name": "رنگ", "value": "قرمز", "confidence": 0.9 },
    { "name": "جنس", "value": "چرم طبیعی", "confidence": 0.7 }
  ],
  "variants": [
    { "type": "رنگ", "options": ["قرمز", "مشکی"] }
  ],
  "missing_info_questions": [
    "قیمت محصول چقدره؟",
    "این محصول چه سایزهایی داره؟"
  ],
  "source_evidence": {
    "from_image": ["رنگ", "جنس ظاهری", "نوع محصول"],
    "from_voice": ["کاربرد", "قیمت"],
    "from_text_on_package": []
  },
  "english": {
    "title": "string",
    "description": "string",
    "attributes": [{"name": "Color", "value": "Red", "confidence": 0.9}]
  }
}
```

نکات کلیدی خروجی:
- هر فیلد استخراج‌شده `confidence` دارد — پلتفرم می‌تواند فیلدهای با اطمینان پایین را برای تأیید دستی هایلایت کند.
- `missing_info_questions` فقط شامل چیزهایی است که از تصویر/صدا قابل استخراج نیست (مثل قیمت) — نه کل فرم.

## جریان کار (Pipeline) نسخه‌ی اول

1. **دریافت ورودی** (عکس‌ها + صدا اختیاری)
2. **تحلیل تصویر** → توضیح بصری محصول (نوع، رنگ، جنس ظاهری، متن روی بسته‌بندی در صورت وجود)
3. **رونویسی صدا (اگر وجود دارد)** → متن فارسی
4. **ادغام شواهد** (تصویر + صدا + hint متنی) → یک نمای واحد از محصول
5. **تولید ساختاریافته** → عنوان، دسته‌بندی، توضیح، ویژگی‌ها، واریانت‌ها
6. **شناسایی شکاف‌های اطلاعاتی** → فقط سؤالات ضروری (قیمت، موجودی، سایزبندی دقیق در صورت نیاز)
7. **بازگشت پیش‌نویس به فروشنده** برای تأیید یا ویرایش

## معماری فنی پیشنهادی (سبک، برای MVP)

```
backend/
  app/
    main.py                  # FastAPI + UI استاتیک /
    config.py                 # env: مدل‌ها، DB، auth، cache، مارکت‌پلیس
    auth.py / storage.py / marketplaces.py
    api/catalog.py            # generate / history / edit / export / publish
    pipeline/
      video.py / vision.py / speech.py / merge.py / generate.py
      retry.py / cache.py / errors.py
    schemas/catalog.py         # ورودی/خروجی + Draft/Update
```

- هر مرحله‌ی pipeline پشت interface ساده است تا بتوان مدل زیرین را عوض کرد.
- جزئیات وضعیت فیچر و قرارداد HTTP: `docs/engine-design.md` و `docs/api.md`.
