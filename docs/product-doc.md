# کاتالوگ‌یار (CatalogYar)
دستیار هوشمند ساخت کاتالوگ محصول

## ۱. مسئله

تجارت آنلاین همچنان از فروشنده می‌خواهد فرم پر کند: عکس آپلود کن، عنوان بنویس، دسته‌بندی انتخاب کن، ویژگی‌ها را پر کن، توضیح محصول بساز.

برای برند بزرگ با تیم محتوا این طبیعی است، اما برای فروشنده‌ی خرد، خانگی، محلی یا اینستاگرامی، **ثبت محصول یکی از سخت‌ترین بخش‌های آنلاین‌شدن است**.

فروشنده محصول را با فرم تجربه نمی‌کند — او محصول را نشان می‌دهد، درباره‌اش حرف می‌زند، از آن ویدئو می‌گیرد، در لایو معرفی می‌کند، در واتساپ برای مشتری ویس و عکس می‌فرستد. غنی‌ترین داده‌ی محصول همین‌جاست: تصویر، گفتار، رنگ، اندازه، جنس، کاربرد. اما پلتفرم همان اطلاعات را دوباره دستی از او می‌خواهد.

**حلقه‌ی معیوب:**
ثبت سخت‌تر ← محصول کمتر ← کاتالوگ ضعیف‌تر ← دیده‌شدن کمتر ← فروش کمتر ← انگیزه‌ی کمتر برای ادامه

### راه‌حل‌های قبلی و محدودیت‌شان
| راه‌حل | مشکل |
|---|---|
| فرم دستی | برای فروشنده‌ی خرد سخت و زمان‌بر است |
| تیم عملیات انسانی (ثبت دستی توسط پلتفرم) | برای پلتفرم گران و غیرمقیاس‌پذیر است |

## ۲. راه‌حل

کاتالوگ‌یار ورودی‌های خامِ فروشنده — عکس، ویدئو، ویس فارسی — را می‌گیرد و به‌جای فرم، یک کاتالوگ ساختاریافته تولید می‌کند:

- دیدن ویدئو/عکس محصول (تشخیص جنس، رنگ، نوع، برند احتمالی، متن روی بسته‌بندی)
- فهم ویس فارسی فروشنده (توضیح شفاهی درباره‌ی کاربرد، سایز، قیمت، ویژگی)
- استخراج ویژگی‌ها و واریانت‌ها (رنگ‌بندی، سایزبندی، جنس)
- پیشنهاد دسته‌بندی، عنوان و توضیح محصول
- پرسیدن سؤال تکمیلی فقط وقتی داده کافی نیست (نه فرم کامل، فقط گپ‌ها)

**اصل تجربه‌ی کاربری:** «محصولت را نشان بده، نه اینکه فرم پر کنی.»

## ۳. بازار هدف

- مارکت‌پلیس‌ها (مثل باسلام)
- فروشگاه‌سازها (SaaS e-commerce builders)
- پلتفرم‌های social commerce (فروش از طریق اینستاگرام/واتساپ)
- پلتفرم‌های لایو کامرس

نقطه‌ی شروع: سناریوی Video-to-Catalog برای فروشندگان خرد باسلام — اما محصول به‌مراتب بزرگ‌تر از یک پروژه‌ی داخلی است؛ گلوگاه هر مارکت‌پلیس و فروشگاه‌سازی است که با رشد فروش آنلاین خرد دائماً بزرگ‌تر می‌شود.

## ۴. محدوده‌ی MVP (نسخه‌ی اول)

جزئیات کامل در `docs/mvp-design.md`. خلاصه‌ی محدوده:

**ورودی:** یک یا چند عکس محصول (+ اختیاری: ویس کوتاه فارسی)
**خروجی:** عنوان پیشنهادی، دسته‌بندی پیشنهادی، توضیح محصول، لیست ویژگی‌های استخراج‌شده، سؤالات تکمیلی (در صورت نیاز)

**خارج از محدوده‌ی MVP (نسخه‌های بعدی):**
- پردازش ویدئو کامل (فریم‌گیری، تشخیص حرکت محصول)
- تشخیص واریانت چندگانه در یک تصویر
- یکپارچگی مستقیم با مارکت‌پلیس‌های شخص ثالث

## ۵. مدل درآمدی

- **B2B SaaS** برای مارکت‌پلیس‌ها و فروشگاه‌سازها (اشتراک ماهانه بر اساس حجم فروشنده)
- **Usage-based per-listing** — هزینه به ازای هر کاتالوگ ساخته‌شده

### اثر شبکه‌ای
هر محصول جدیدی که پردازش می‌شود، مدل را در تشخیص دسته‌بندی و ویژگی دقیق‌تر می‌کند (بهبود مستمر با داده‌ی بیشتر).

## ۶. نقشه راه (پیشنهادی)

| فاز | محتوا |
|---|---|
| فاز ۰ — MVP | عکس → کاتالوگ (عنوان، دسته، توضیح، ویژگی) |
| فاز ۱ | افزودن ورودی ویس فارسی |
| فاز ۲ | افزودن ورودی ویدئو (فریم‌گیری، OCR بسته‌بندی) |
| فاز ۳ | تشخیص واریانت‌های چندگانه (رنگ/سایز) از یک ست ورودی |
| فاز ۴ | یکپارچگی API با مارکت‌پلیس‌ها/فروشگاه‌سازها (B2B) |
| فاز ۵ | حلقه‌ی یادگیری از بازخورد فروشنده/پلتفرم برای بهبود دقت |

## ۷. معیارهای موفقیت (پیشنهادی)

- درصد کاتالوگ‌هایی که بدون ویرایش دستی فروشنده تأیید می‌شوند
- کاهش زمان متوسط ثبت محصول (از فرم چند دقیقه‌ای به چند ثانیه)
- افزایش نرخ تکمیل ثبت محصول (drop-off کمتر)
- افزایش تعداد محصولات ثبت‌شده به ازای هر فروشنده فعال
